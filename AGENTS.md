# AGENTS.md

Guidance for coding agents working in this repo.

## What it is

An Obsidian plugin that turns "run this workflow" instructions in a note into a clickable button. Clicking it fires Claude Code or OpenCode at the note in a live xterm.js terminal under the button (or silently in the background), dropping the result into the note when done.

## Stack

- TypeScript, bundled with esbuild (CJS, target ES2020).
- Obsidian plugin API (`obsidian`), desktop-only (`isDesktopOnly: true`).
- `@xterm/xterm` + `@xterm/fit` for terminal rendering.
- PTY via shelling out to `python3 -c "import pty,sys; pty.spawn(sys.argv[1:])"` (no native `node-pty` build).
- ESLint with `eslint-plugin-obsidianmd` (community-plugin lint rules, non-suppressible).
- Docs: MkDocs site under `docs/`.

## Commands

- Install: `npm install`.
- Dev/watch build: `npm run dev` (`node esbuild.config.mjs`).
- Build: `npm run build` (`tsc -noEmit -skipLibCheck && node esbuild.config.mjs production`).
- Lint: `npm run lint` (`eslint src/`).
- Test: no test script is defined in `package.json` yet.

## Where things live

- `src/main.ts`: plugin entry point.
- `src/agents.ts`: agent (Claude Code / OpenCode) definitions.
- `src/buttonBlock.ts`: renders the `agent-button` code block widget.
- `src/runner.ts`: resolves the agent binary (`resolveBinary()`) and spawns the PTY via python3 (with the "why not node-pty / why not BSD script" reasoning).
- `src/outputCapture.ts`: reads xterm.js's rendered screen (not raw ANSI) for turn-completion detection and clean-text extraction.
- `src/context.ts`: builds the per-click note context snapshot for templating.
- `src/templating.ts`: renders `{{ }}` lookups and dispatches `{{= }}` expressions.
- `src/expr.ts`: hand-written parser/interpreter for the `{{= }}` expression language (no `eval`/`new Function`).
- `src/fileOutput.ts`: writes captured output into the note (`append` positions).
- `src/settings.ts`: plugin settings (default agent, auto-approve, model mappings, JS-expression toggle).
- `esbuild.config.mjs`: build config; its banner marks `main.js` as generated.
- `manifest.json` / `package.json` / `versions.json`: Obsidian plugin manifest and npm metadata.
- `docs/`: MkDocs documentation site (`docs/docs/*.md`), deployed via `.github/workflows/documentation.yml`.
- `.github/workflows/release.yml`: release automation.
- `styles.css`: plugin styles.

## Conventions

- Edit only `src/*.ts`; `main.js` is generated by esbuild. Never edit it directly.
- No `eval`/`new Function` anywhere. `eslint-plugin-obsidianmd` flags it and the rule is non-suppressible, a hard constraint for community-plugin submission.
- `{{= }}` logic is a closed-grammar interpreter (`src/expr.ts`), not sandboxed JS: no assignment, no loops, no access outside the context object, a fixed set of callable helper names.
- Turn-completion and output extraction read xterm.js's rendered 2D grid (`src/outputCapture.ts`), not the raw ANSI stream.
- Agent binary resolution falls through known install paths per OS/environment, then a bare command name for `PATH` lookup. Never hard-fail on one assumed location (`resolveBinary()` in `src/runner.ts`).
- `tsconfig.json` enforces `noImplicitAny` and `strictNullChecks`.

## Product rules

- Every `agent-button` field except `text` and `prompt` is optional and falls back to a sensible default.
- No `model:` line means no `--model` flag is passed at all; the CLI uses its own default.
- `{{= }}` expressions are off by default. While off, a prompt containing `{{= }}` writes an error to the terminal and does not run (never silently sent as literal text). They're enabled via **Allow JavaScript expressions in prompts** in Settings.
- An unknown root name in a plain `{{ }}` lookup (e.g. a typo) is left untouched in the prompt; a missing value under a known root renders as an empty string.
- `append: belowButton` snapshots the button's position at click time and sanity-checks it against the note's current content before inserting. If the note changed shape, it falls back to `bottom` rather than risk inserting in the wrong place.
- `completion: manual` (default) never auto-clears the button's loading state. Only a manual terminal/note close or the "Complete" checkmark button does, and clicking it kills the session.
- `completion: responseEnd` clears the spinner on detecting Claude Code's turn-completion marker but does **not** kill the session. If the agent is blocked on a prompt or question instead, the spinner becomes a ✏️ icon rather than clearing. This detection is tuned to Claude Code's output and is unverified for OpenCode.
- `agentOutput: file` only changes where the final captured output goes; the live terminal accordion during the run is still controlled by `showTerminal`.
- The plugin is desktop-only (`isDesktopOnly: true` in `manifest.json`).
